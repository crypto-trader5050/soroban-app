商品化方針

目標価格：

月額5,000円を基本ラインとして検討。

販売時には、

問題作成の手間を減らせる

検定対策問題を作れる

フラッシュ暗算をすぐ使える

読み上げを先生の代わりに行える

教室で簡単に使える

という「先生の負担軽減」を価値として訴求する。

開発方針

全部作ってから販売するのではなく、販売可能な最小構成を早期に作り、実際の先生から意見を得て改善する。

また、既存機能を修正するときは、見取り算など他種目への影響を確認してから変更する。

重要な設計思想

3本柱を崩さない

入口は「フラッシュ暗算・問題作成・読み上げ」の3つ。

機能の重複を避ける

独立した「練習チャレンジ」などを増やさず、必要な機能は3本柱の中に組み込む。

正確性と速さを分離する

速さは重要だが、現在のフラッシュ暗算の合否は正解数を基本とする。

先生の操作を最優先する

ITが得意ではない先生でも迷わず使えるUIを目指す。

壊さない

既存機能を変更するときは、他種目への影響を確認してから変更する。

【STEP 1】3日間の実証テスト
🟢 1日目：ローカル音声クローンを動かす

目的：あなたの声をAIに覚えさせて、実際にしゃべらせる。

やること：

PC環境確認
必要なソフトをインストール
ローカルTTS環境構築
あなたの声を録音
音声データを加工
音声クローンを作成
「1」「25」「1234」などを読ませる
1日目のゴール

「自分の声でAIが数字を読んだ！」

ここまで。

【STEP 2】2日目：そろばん専用音声を作る

ここが非常に重要です。

普通の数字読み上げではなく、

固定フレーズ
「ねがいましては」
「えんなり」
「ひいては」
「くわえて」
「では」
「ご名算です」

をあなたの声で読ませます。

さらに、

1桁 → 2桁 → 3桁 → 4桁……

と数字を大量にテストします。

そして、

「ここは速すぎる」
「ここはもっと間を空けたい」
「この数字の読み方が変」
「ここは強く読みたい」

という感じで修正します。

2日目のゴール

「普通のTTS」ではなく「そろばん用の読み上げ」として使える状態。

【STEP 3】3日目：現在のアプリと接続

ここで初めて、今作っているアプリに接続します。

例えば、

問題生成
↓
「7 → 32 → 5 → 81 → 6」
↓
読み上げ用データ作成
↓
ローカルTTS
↓
あなたの声
↓
再生

という流れにします。

そして実際に、

10～20問程度をランダム生成して連続再生

します。

3日目の判定

ここで一度、私たちが判断します。

A：かなり良い
→ この方式を採用して本格的に品質向上。

B：使えるが改善が必要
→ 音声・速度・間・数字の発音を調整。

C：声質が納得できない
→ 別のローカルモデルを試す。
